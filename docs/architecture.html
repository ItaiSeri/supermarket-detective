Supermarket Detective

Israeli supermarket chains must publish every price and promotion, every day. This pipeline collects those files in the cloud, keeps the full price history, and asks questions like: is Eilat really 15.3% cheaper without VAT, and which "promotions" aren't cheaper at all?

Two ways data comes in

History prep fills the past once. The daily run keeps it current. They share everything from S3 on, so the pipeline in Databricks is written once.

How a daily full file becomes price history

Every day each chain republishes its whole price list. Silver keeps a new row only when a price actually changes, with the dates it was valid. That's an SCD Type 2 table, and the same "source sends a full dump" problem as a nightly bank extract.

Why this stack

Each choice had to fit three limits: everything scheduled runs in the cloud, it costs a few dollars a month at most, and it shows the tools Israeli job ads ask for.

Where ingestion runs
AWS, Tel Aviv region
Instead of the home PC, GitHub Actions, a Databricks job

It has to run in the cloud, and 7 chains block foreign traffic, so it needs an Israeli address. Tested on 2026-11-03: a Lambda here downloaded files from all 7. GitHub's runners are outside Israel.

Compute
Lambda, one run per chain + file type
Instead of Fargate, Lambda Managed Instances

A whole Shufersal day doesn't fit in Lambda's 15 minutes, so each chain is split by file type; Shufersal's prices alone took 10.5 minutes. Each file is zipped, uploaded and deleted as it arrives, so a full chain never fills the 2 GB disk. Lambda is close to free at this volume. Managed Instances allow 90 minutes but bill EC2 servers even when idle. Fargate stays the fallback if a chain ever needs longer.

Orchestration
Step Functions
Instead of Airflow (MWAA), Lambda durable functions, Databricks Jobs

The Map state runs the 30 inputs in parallel with retries per item, and every run shows as a visual graph, which is good for a portfolio. An always-on managed Airflow environment starts above $200 a month. Durable functions could also do it, but they don't give the visual run graph. Databricks Jobs can't reach the chain sites.

Raw archive
S3, versioned
Instead of only the Databricks volume

Databricks may delete a free account after long inactivity. S3 is the copy of record, and Databricks reads it directly through a read-only external location, so raw is not copied. Every table can be rebuilt from it, and history that was missed can't be recollected later. It costs cents a month.

Sources
Own scraper + Kaggle
Instead of Kaggle only or scraper only

Kaggle gives two years of history and a fallback for a chain whose site is down, but it is already converted to CSV, and the store id appears only on each file's first row. The scraper gives the raw XML, which is the real integration work. On days both cover a chain, the pipeline compares them.

Lakehouse
Databricks Free Edition
Instead of Snowflake, BigQuery, Microsoft Fabric, DuckDB + dbt

It's free with no time limit, while the Snowflake trial ends after 30 days and Fabric's after 60. Israeli enterprises moving off Oracle and DataStage are adopting it. DuckDB is free too, but job ads don't ask for it.

Transformation
Lakeflow declarative pipeline
Instead of dbt, notebooks with hand-written MERGE

Quality rules (expectations) and SCD2 history (AUTO CDC) are built in. Free Edition allows one active pipeline per type, so one pipeline covers all chains. dbt can come later as an extra.

Reporting
Power BI
Instead of Databricks dashboards, Tableau

Power BI was the most common gap in your saved jobs (39 of 128). Power BI Desktop is free. Databricks' Genie can still be a live "ask the data" demo on top.

Setup as code
Terraform + Databricks bundles
Instead of clicking in the consoles

Terraform creates the AWS resources, and a bundle defines the Databricks pipeline and jobs, so the repo can rebuild everything. It's also a common interview topic.
