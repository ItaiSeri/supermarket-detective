Supermarket Detective

Israeli supermarket chains must publish every price and promotion, every day. This pipeline collects those files in the cloud, keeps the full price history, and asks questions like: is Eilat really 15.3% cheaper without VAT, and which "promotions" aren't cheaper at all?

Pipeline first, then where each piece of data lives, then the gold layer design (milestone 4): tables, questions and decisions.

Where each piece of data lives

Raw files stay in our own S3 buckets, in two regions. Every table is a managed Delta table: Databricks keeps its files in its own storage in Ohio, next to the compute, not in our AWS account. There are no external tables left. One gold fact is a view, so it stores nothing.

How a daily full file becomes price history

Every day each chain republishes its whole price list. Silver keeps a new row only when a tracked value changes (price, unit price, package size, flags), with the first and last day it was seen. A store's file that arrives without the product also ends a period; a day with no file doesn't. That's an SCD Type 2 table, and the same "source sends a full dump" problem as a nightly bank extract.

Why this stack

Each choice had to fit three limits: everything scheduled runs in the cloud, it costs a few dollars a month at most, and it shows the tools Israeli job ads ask for.

Where ingestion runs
AWS, Tel Aviv region
Instead of the home PC, GitHub Actions, a Databricks job

It has to run in the cloud, and 7 chains block foreign traffic, so it needs an Israeli address. Tested on November 3rd, 2026: a Lambda here downloaded files from all 7. GitHub's runners are outside Israel.

Compute
Lambda, one run per chain + file type
Instead of Fargate, Lambda Managed Instances

A whole Shufersal day doesn't fit in Lambda's 15 minutes, so each chain is split by file type; Shufersal's prices alone took 10.5 minutes. Each file is zipped, uploaded and deleted as it arrives, so a full chain never fills the 2 GB disk. Lambda is close to free at this volume. Managed Instances allow 90 minutes but bill EC2 servers even when idle. Fargate stays the fallback if a chain ever needs longer.

Orchestration
Step Functions
Instead of Airflow (MWAA), Lambda durable functions, Databricks Jobs

The Map state runs the 30 inputs in parallel with retries per item, and every run shows as a visual graph, which is good for a portfolio. An always-on managed Airflow environment starts above $200 a month. Durable functions could also do it, but they don't give the visual run graph. Databricks Jobs can't reach the chain sites.

Raw archive
S3, versioned
Instead of only the Databricks volume

Databricks may delete a free account after long inactivity. S3 is the copy of record, and Databricks reads it directly through a read-only external location, so raw is not copied. Every table can be rebuilt from it, and history that was missed can't be recollected later. It costs cents a month.

Sources
Own scraper + Kaggle
Instead of Kaggle only or scraper only

Kaggle gives two years of history, but it is already converted to CSV and sparse: a value equal to the row above is left blank in every column, so bronze fills each blank from the row above inside the file's block (checked against an independent pandas fill: same rows, same values). The scraper gives the raw XML, which is the real integration work. Where both hold the same source file, a data-quality check compares them.

Lakehouse
Databricks Free Edition
Instead of Snowflake, BigQuery, Microsoft Fabric, DuckDB + dbt

It's free with no time limit, while the Snowflake trial ends after 30 days and Fabric's after 60. Israeli enterprises moving off Oracle and DataStage are adopting it. DuckDB is free too, but job ads don't ask for it.

Transformation
Notebooks with SQL and MERGE, run as Databricks jobs
Instead of a Lakeflow declarative pipeline (the plan on November 3rd, 2026), dbt

Each rule is written out and kept in Git: SCD2 that treats a missing file differently from a missing product, quarantine with a reason per row, row-count reconciliation, data-quality checks with PASS / WARNING / FAIL. Jobs chain the layers (daily_load runs bronze, silver, gold), and each MERGE skips rows already saved, so a re-run adds nothing. dbt can come later as an extra.

Reporting
Power BI
Instead of Databricks dashboards, Tableau

Power BI was the most common gap in your saved jobs (39 of 128). Power BI Desktop is free. Databricks' Genie can still be a live "ask the data" demo on top.

Setup as code
Terraform + Databricks bundles
Instead of clicking in the consoles

Terraform creates the AWS resources, and a bundle defines the Databricks jobs and notebooks, so the repo can rebuild everything. It's also a common interview topic.

1 · Lineage

From the chains' websites to a chart

Raw files are kept untouched in S3. Bronze holds every value as published, silver cleans and keys it, and gold shapes it for questions. The big tables stay in Databricks, and Power BI imports only the small gold marts and the dimensions they use.

2 · Gold tables

A small star, plus one mart per question

The star (3 dimensions, 2 facts) is the only thing that reads silver. Every mart reads only the star, so keys, filters (physical store, shared barcode) and business rules live in one place, and two charts can't disagree because they took a shortcut to silver. A fact is stored as a table only when building it does real work (changes the grain, or is too expensive to repeat); otherwise it's a view over silver. Marts are always tables, rebuilt daily. The one exception is ops_health, which reads pipeline metadata, not prices.

Store-wide promotions (a promotion listing more than 10,000 products: coupons, donations, delivery fees) stay in silver and are not in gold: they are not deals on products (decided November 17th, 2026). Product deals have one row per store × promotion × group × product. A promotion ID is the deal's identity, so the row is never split by its values: chains re-encode the same deal from day to day (Shufersal's 1+1 as 50% / 19.90 one day, 100% / 0.00 the next). The last day's values are kept, and values_changed flags a deal whose values differed. A product in two promotions at once gets two rows.

3 · First finding
0.847

Median price of the same product in the same chain, Eilat vs the rest of the country, today (current prices at physical stores). 1 / 1.18 = 0.847, so the 18% VAT exemption reaches the shelf in Shufersal (0.847), Mahsani Ashuk (0.847) and Rami Levy (0.855). In Carrefour the median is 1.000, no discount at all on most products. That's the first post, once Carrefour's case is checked.
